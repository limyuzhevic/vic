# NLM CLI - Configuration Management

## Overview

This document provides comprehensive information about NLM configuration management for the Command Line Interface (CLI). It covers configuration file format, parameter validation, phase-specific settings, and best practices.

## Configuration Management

The NLM CLI provides robust configuration management through:

1. **Command-line arguments** for runtime configuration
2. **Configuration files** (`.cfg`) for persistent settings
3. **Programmatic configuration** through the API
4. **Configuration validation** with suggestions
5. **Configuration inheritance** and precedence

## Configuration File Format

### Basic Format

NLM configuration files use a simple key-value format:

```ini
# NLM Configuration File
# Generated by NLM CLI

# Basic settings
neuron_count = 1000
region_count = 1
connection_probability = 0.1

# Neural parameters
random_seed = 42
simulation_timestep = 0.001
stdp_ltp_weight = 0.02
stdp_ltd_weight = 0.015
stdp_tau = 20.0

# Plasticity parameters
synaptogenesis_rate = 0.0001
pruning_rate = 0.00001

# Comments are indicated with #
# Empty lines are ignored
```

### File Structure

```
configs/
├── default.cfg          # Default configuration
├── phase2.cfg           # Phase 2 specific settings
├── phase3.cfg           # Phase 3 specific settings
├── phase4.cfg           # Phase 4 specific settings
├── phase5.cfg           # Phase 5 specific settings
├── phase6.cfg           # Phase 6 specific settings
└── custom.cfg           # Custom configuration
```

## Configuration Sources and Precedence

### Source Priority

Configuration sources are applied in this order (later sources override earlier ones):

1. **Runtime (Command Line)** - Highest priority
2. **File** - Medium priority
3. **Default** - Lowest priority

### Configuration Inheritance

Parameters can inherit from parent configurations:

- **Phase Inheritance**: Phase 3 parameters inherit from Phase 2
- **Region Inheritance**: Regions inherit parameters from parent regions
- **Population Inheritance**: Populations inherit parameters from parent populations

## Configuration Validation

### Validation Rules

Configuration validation checks for:

1. **Type validation**: Ensures parameters have correct types
2. **Range validation**: Ensures parameters are within valid ranges
3. **Dependency validation**: Ensures dependent parameters are valid
4. **Uniqueness validation**: Ensures unique identifiers
5. **Consistency validation**: Ensures configuration consistency

### Validation Errors

Common validation errors and their solutions:

| Error Type | Description | Solution |
|------------|-------------|----------|
| `INVALID_TYPE` | Parameter has wrong type | Use correct type (int, float, string, etc.) |
| `OUT_OF_RANGE` | Parameter outside valid range | Use value within specified range |
| `MISSING_DEPENDENCY` | Required dependency missing | Set required dependency |
| `DUPLICATE_ID` | Duplicate identifier | Use unique identifier |
| `INCONSISTENT_STATE` | Inconsistent configuration | Review configuration for conflicts |

### Validation Commands

```bash
# Validate current configuration
nlm config validate

# Get validation errors
nlm config validate --show_errors

# Fix validation issues
nlm config suggestions
```

## Configuration Commands

### `config get <key>`

Get configuration value.

#### Usage Examples

```bash
# Get basic configuration
nlm config get neuron_count
nlm config get connection_probability

# Get nested configuration
nlm config get phase3.planning_depth
```

#### Output Format

```
Configuration value:
  neuron_count = 1000
  Type: int64
  Source: File
  Last used: 2024-01-15 10:30:00
```

### `config set <key> <value>`

Set configuration value.

#### Usage Examples

```bash
# Set basic configuration
nlm config set neuron_count 2000
nlm config set connection_probability 0.15

# Set phase-specific configuration
nlm config set phase6.working_memory_capacity 0.2
nlm config set phase3.concept_threshold 0.8
```

#### Validation

Setting configuration values triggers validation:

1. **Type validation**: Check if value matches expected type
2. **Range validation**: Check if value is within valid range
3. **Dependency validation**: Check if dependencies are valid

### `config load <filepath>`

Load configuration from file.

#### Usage Examples

```bash
# Load configuration from file
nlm config load my_config.cfg

# Load default configuration
nlm config load configs/default.cfg

# Load configuration with override
nlm --config my_config.cfg run phase6
```

#### File Format Support

- **INI format**: Key-value pairs with comments
- **JSON format**: Structured configuration
- **YAML format**: Human-readable configuration
- **XML format**: Structured configuration

### `config save <filepath>`

Save current configuration to file.

#### Usage Examples

```bash
# Save current configuration
nlm config save current_config.cfg

# Save configuration with timestamp
nlm config save configs/config_$(date +%Y%m%d_%H%M%S).cfg

# Save configuration with metadata
nlm config save --include_metadata --include_suggestions configs/config.cfg
```

#### File Options

- **`--include_metadata`**: Include configuration metadata
- **`--include_suggestions`**: Include improvement suggestions
- **`--overwrite`**: Overwrite existing file
- **`--validate`**: Validate before saving

### `config validate`

Validate current configuration.

#### Usage Examples

```bash
# Basic validation
nlm config validate

# Detailed validation with errors
nlm config validate --show_errors --fix

# Validate specific parameters
nlm config validate --key neuron_count
```

#### Validation Output

```
=== Configuration Validation ===
Overall status: VALID

Parameter validation:
  neuron_count: VALID (1000)
  connection_probability: VALID (0.1)
  random_seed: VALID (42)

Dependency validation:
  All dependencies satisfied

Consistency validation:
  Configuration is consistent

Warnings:
  - Consider increasing neuron_count for better performance
  - Connection probability is low, may affect learning
```

### `config suggestions <partial_key>`

Get configuration suggestions.

#### Usage Examples

```bash
# Get suggestions for 'neuron'
nlm config suggestions neuron

# Get suggestions for 'phase3'
nlm config suggestions phase3

# Get suggestions for configuration issues
nlm config suggestions --issues
```

#### Suggestion Types

1. **Parameter suggestions**: Suggest parameter values
2. **Optimization suggestions**: Suggest performance improvements
3. **Compatibility suggestions**: Suggest compatible configurations
4. **Issue suggestions**: Suggest fixes for configuration issues

## Configuration Best Practices

### 1. Keep Configurations Simple

- Use descriptive parameter names
- Avoid unnecessary parameters
- Group related parameters together

### 2. Use Meaningful Values

- Use meaningful default values
- Document parameter ranges
- Consider system capabilities

### 3. Validate Configurations

- Always validate configurations before use
- Use `nlm config validate` regularly
- Fix validation errors promptly

### 4. Test Configurations

- Test configurations with different scenarios
- Profile performance with different settings
- Monitor resource usage

### 5. Document Configurations

- Document configuration purpose
- Document parameter dependencies
- Document performance implications

## Troubleshooting Configuration Issues

### Common Issues

1. **"Configuration validation failed"**
   - Solution: Use `nlm config validate` to see specific errors
   - Fix: Correct validation errors

2. **"File not found"**
   - Solution: Check file path and ensure file exists
   - Fix: Create or move file to correct location

3. **"Permission denied"**
   - Solution: Check file permissions
   - Fix: Change file permissions or run with appropriate privileges

4. **"Configuration inconsistency"**
   - Solution: Review configuration for conflicts
   - Fix: Remove conflicting parameters

5. **"Performance issues"**
   - Solution: Optimize configuration for performance
   - Fix: Adjust parameters or use different configuration

### Configuration Recovery

```bash
# Reset to default configuration
nlm config load configs/default.cfg

# Fix broken configuration
nlm config save --overwrite --validate fixed_config.cfg

# Create backup before changes
nlm config save backups/config_before_$(date +%Y%m%d).cfg
```

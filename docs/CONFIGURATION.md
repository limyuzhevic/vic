# NLM Configuration Schema and Validation

## Overview

NLM includes a comprehensive configuration system with validation capabilities to ensure configuration files are valid and complete before use.

## Configuration Schema

The configuration system supports multiple data types and provides validation for each key-value pair.

### Supported Configuration Types

1. **Integer Types**
   - `int`, `int64_t`
   - Examples: `random_seed = 42`, `neuron_count = 1000`

2. **Floating Point Types**
   - `double`
   - Examples: `simulation_timestep = 0.001`, `stdp_ltp_weight = 0.02`

3. **Boolean Types**
   - `bool`
   - Examples: `log_to_file = false`, `visualization_enabled = true`

4. **String Types**
   - `std::string`
   - Examples: `environment_name = "GridWorld"`, `log_filename = "nlm.log"`

5. **Array Types**
   - `std::vector<int>`, `std::vector<double>`, `std::vector<std::string>`
   - Examples: `some_list = [1, 2, 3]`, `string_list = ["option1", "option2"]`

## Configuration Schema Definition

Configuration schemas define expected types, required status, and validation rules for configuration keys.

### Schema Structure

```cpp
struct ConfigSchema {
    std::string key;                    // Configuration key
    std::set<std::string> allowedTypes; // Expected data types
    std::optional<std::string> defaultValue; // Default value if missing
    bool required;                       // Whether the key is required
    std::string description;            // Human-readable description
    std::function<bool(const ConfigValue&)> validator; // Custom validation function
};
```

### Example Schema Definition

```cpp
// Define common configuration schemas
std::vector<ConfigSchema> commonSchemas = {
    {"random_seed", {"int", "int64_t"}, false, "42", "Random seed for reproducible experiments"},
    {"simulation_timestep", {"double"}, false, "0.001", "Simulation timestep in seconds"},
    {"neuron_count", {"int", "int64_t"}, false, "1000", "Number of neurons in the brain"},
    {"region_count", {"int", "int64_t"}, false, "1", "Number of brain regions"},
    {"connection_probability", {"double"}, false, "0.1", "Connection probability for random connectivity"},
    {"stdp_ltp_weight", {"double"}, false, "0.02", "STDP LTP weight"},
    {"stdp_ltd_weight", {"double"}, false, "0.015", "STDP LTD weight"},
    {"log_level", {"string"}, false, "INFO", "Logging level"},
    {"log_to_file", {"bool"}, false, "false", "Write logs to file"},
};
```

## Configuration Validation

### Validation Process

Configuration validation occurs in two phases:

1. **Type Validation**: Ensures each configuration value matches the expected type
2. **Required Field Validation**: Checks if all required fields are present
3. **Custom Validation**: Applies custom validation functions if provided

### Validation Result

```cpp
struct ConfigValidationResult {
    bool isValid;              // Overall validation status
    std::string errorMessage;  // Detailed error message if invalid
    std::string path;          // Configuration key path for nested configs
};
```

### Example Validation

```cpp
// Register configuration schemas
Config::registerSchema("common", commonSchemas);

// Validate a configuration
Config config;
config.loadFromFile("configs/default.cfg");

ConfigValidationResult result = Config::validate(config, commonSchemas);

if (!result.isValid) {
    std::cerr << "Configuration validation failed:" << std::endl;
    std::cerr << result.errorMessage << std::endl;
    return 1;
}
```

## Command Line Configuration Overrides

Command line arguments provide a convenient way to override configuration file settings:

### Basic Overrides

```bash
# Override single settings
./nlm --neurons 2000 --regions 3 --timestep 0.5

# Use custom configuration file
./nlm --config myconfig.cfg

# Save brain state after tests
./nlm --save-state brain_checkpoint.chk
```

### Advanced Overrides

```bash
# Override multiple settings
./nlm --test-mode plasticity --neurons 1500 --seed 12345 --log-level debug

# Custom log file
./nlm --logfile nlm_debug.log --log-level debug

# Development mode
./nlm --test-mode all --config dev.cfg --save-state dev_state.chk
```

### Configuration Override Format

Command line arguments follow these formats:

```bash
--key=value                    # Short format
--key value                    # Long format
-key value                    # Short key format
```

## Configuration Validation Examples

### Custom Validation Function

```cpp
// Custom validation for learning rate
bool validateLearningRate(const ConfigValue& value) {
    if (!std::holds_alternative<double>(value)) {
        return false;
    }
    double learningRate = std::get<double>(value);
    return learningRate >= 0.0 && learningRate <= 1.0;
}

// Create schema with custom validation
ConfigSchema learningRateSchema = {
    "plasticity_learning_rate", {"double"}, false, "0.01",
    "Learning rate for plasticity rules",
    validateLearningRate
};
```

### Configuration Error Handling

```cpp
// Load and validate configuration with error handling
bool loadAndValidateConfig(const std::string& configFile, const std::vector<ConfigSchema>& schema) {
    Config config;
    
    // Load configuration
    if (!config.loadFromFile(configFile)) {
        std::cerr << "Failed to load configuration from: " << configFile << std::endl;
        return false;
    }
    
    // Validate configuration
    ConfigValidationResult result = Config::validate(config, schema);
    
    if (!result.isValid) {
        std::cerr << "Configuration validation failed:" << std::endl;
        std::cerr << result.errorMessage << std::endl;
        std::cerr << "Path: " << result.path << std::endl;
        return false;
    }
    
    std::cout << "Configuration loaded and validated successfully." << std::endl;
    return true;
}
```


## Configuration Validation in Practice

### Complete Example

```cpp
// Complete configuration validation example
#include "core/Config/Config.hpp"
#include <iostream>

int main() {
    // Define configuration schema
    std::vector<ConfigSchema> schema = {
        {"random_seed", {"int", "int64_t"}, false, "42", "Random seed for reproducible experiments"},
        {"simulation_timestep", {"double"}, false, "0.001", "Simulation timestep in seconds"},
        {"neuron_count", {"int", "int64_t"}, false, "1000", "Number of neurons in the brain"},
        {"region_count", {"int", "int64_t"}, false, "1", "Number of brain regions"},
        {"connection_probability", {"double"}, false, "0.1", "Connection probability"},
        {"log_level", {"string"}, false, "INFO", "Logging level"},
    };
    
    // Register schema
    Config::registerSchema("nlm", schema);
    
    // Load configuration
    Config config;
    if (!config.loadFromFile("configs/default.cfg")) {
        std::cerr << "Failed to load configuration" << std::endl;
        return 1;
    }
    
    // Validate configuration
    ConfigValidationResult result = Config::validate(config, schema);
    
    if (!result.isValid) {
        std::cerr << "Configuration validation failed:" << std::endl;
        std::cerr << result.errorMessage << std::endl;
        return 1;
    }
    
    // Configuration is valid, proceed with initialization
    std::cout << "Configuration validated successfully!" << std::endl;
    
    // Use configuration values
    int seed = config.getOr<int64_t>("random_seed", 42);
    double timestep = config.getOr<double>("simulation_timestep", 0.001);
    int neurons = config.getOr<int64_t>("neuron_count", 1000);
    
    std::cout << "Using configuration:" << std::endl;
    std::cout << "  Random seed: " << seed << std::endl;
    std::cout << "  Timestep: " << timestep << std::endl;
    std::cout << "  Neurons: " << neurons << std::endl;
    
    return 0;
}
```

## Conclusion

The NLM configuration system provides comprehensive validation and documentation to ensure reliable configuration management. Key features include:

- **Type Validation**: Ensures configuration values match expected types
- **Required Field Validation**: Checks for required configuration keys
- **Custom Validation**: Supports custom validation functions
- **Schema Management**: Register and manage configuration schemas
- **Error Reporting**: Detailed error messages for validation failures
- **Documentation**: Comprehensive configuration documentation

These improvements make the NLM configuration system more robust, user-friendly, and maintainable.
